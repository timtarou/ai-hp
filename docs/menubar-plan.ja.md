# ai-hp メニューバーアプリ計画

作成日: 2026-09-26 / 調査対象: main `c4b9ed1`（v0.5.0）

## 目的と推奨構成

macOSのメニューバーから、Claude / Codexの複数アカウントの残り枠とリセット時刻を確認できるようにする。まず本人のMacで日常利用できるMVPを作り、その後に配布を整える。

推奨は **SwiftUIのメニューバーアプリ + 既存TypeScriptの取得処理**。macOS 13以降を対象に `MenuBarExtra` を使う。アプリは `node cli.js --json` を子プロセスとして呼び出す。認証と利用枠の取得は引き続き既存のclaude / codex CLIに任せる。

| 案 | 利点 | 負担 | 判断 |
|---|---|---|---|
| SwiftUI + Node取得処理 | macOSに馴染むUI、既存の取得ロジックを共有 | SwiftとNodeの接続・配布が必要 | 推奨 |
| メニューバーツール用スクリプト | 小さく試せる | 別アプリへの依存、独自UIの制約 | 表示だけの試作向け |
| Swiftで全処理を再実装 | Node不要 | CLIプロトコル対応・解析処理が二重になる | MVPでは採用しない |

## 調査で確認した現状

- `skills/ai-hp/scripts/cli.ts` に取得、重複統合、キャッシュ、表示のオーケストレーションがまとまっている。`--json` はない。
- `types.ts` の `Snapshot` / `Limit` がUI向けの元データとして使える。週間、モデル別、短期、banked resetを保持する。
- `collect/claude.ts` と `collect/codex.ts` は独立している。`jsonl-process.ts` が子プロセスの通信とタイムアウトを担当する。
- キャッシュは14日保存される。常駐UIでは保持期限とは別に、表示値の鮮度を示す必要がある。
- `detect.ts` はPATHと一般的なインストール先を探す。GUI起動時のPATHやバージョン管理ツール配下のNodeは追加対応が必要。
- このシェルのNodeはv20.20.2。リポジトリのテスト実行にはREADME上Node 22.18以降が必要。Xcodeの選択先はCommand Line Toolsであり、ネイティブビルド環境は実装開始時に確認する。

## MVPの操作と表示

1. メニューバーは選択したアカウントの週間残量を短く表示する（例: `C 62%`）。初回はアイコンのみとし、パネルから固定するアカウントを選ぶ。複数アカウントの割合は合算しない。
2. クリックすると、週間リセットが近い順に全アカウントを表示する。日時不明は末尾。同じメールでもプランや組織が異なる行を区別する。
3. 各行にサービス、メールまたは別名、プラン、週間HPバー、モデル別枠、短期枠、次回リセット、banked resetと期限を表示する。
4. 「今すぐ更新」「設定」「終了」を配置する。設定は表示アカウント、更新間隔、メールを隠す、ログイン時起動を対象にする。
5. 読込中、アカウントなし、CLIなし、未ログイン、部分失敗、オフラインを区別する。古い値には取得時刻と「前回取得」を表示する。未取得や未対応を0%・0回で埋めない。
6. リセット予定時刻を過ぎても、再取得に成功するまでは100%になったと推測しない。

アカウント追加は「アカウントを追加」→Claude / Codex選択→既存CLIのブラウザログインとする。`ai-hp connect [claude|codex]` で名前・保存先の指定を省略できる。メニューバーからの呼び出し時はCLIの対話・キャンセルを扱う導線を実装する。

初版の対象外: アカウントの自動切替、リセット権の使用、独自の認証処理、通知、自動アップデート。

## 実装順序と完了条件

### 1. 取得処理の分離とJSON契約

- `cli.ts` から表示に依存しない取得関数を `collect.ts` へ抽出する。既存CLIとスキルの出力を維持する。
- `--json` を追加。`schemaVersion`、`generatedAt`、アカウント一覧、鮮度、構造化した取得エラー・除外理由を返す。
- 日時はISO 8601、割合は数値、未知・未対応・対象なしは明示的な状態にする。翻訳済みMarkdownを解析しない。
- stdoutはJSON一件のみ、診断はstderr。全体失敗でも可能な範囲でJSONを返し、終了コードとエラーの扱いを文書化する。
- キャッシュは現状のatomic renameによる最終書込優先。アプリには `AI_HP_CACHE` で専用ファイルを指定し、アプリ内の取得を一件に制限してCLIとの更新競合を避ける。

完了条件: 通常、部分失敗、全失敗、未ログイン、キャッシュのみのfixtureでJSON契約を検証し、既存テスト・型検査・ビルド整合性確認が通る。

### 2. メニューバーUI

- `apps/macos/` にSwiftUIアプリを追加。`MenuBarExtra` のwindow形式でアカウントカードを表示し、Dockへの常時表示は行わない。
- SwiftのDecodableモデルでJSONを読む。固定アカウントは安定したaccountKeyで保持する。固定先がなくなった場合は選び直せる状態を表示する。
- まずfixtureで通常・空・エラー・古い値の画面を実装し、実CLIに接続する。
- ダークモード、長いメール、複数アカウントのスクロール、VoiceOver、色以外による残量の識別を確認する。

完了条件: パネルを開いて必要な枠が読める。更新中でもUI操作が止まらず、設定と固定アカウントが再起動後に維持される。

### 3. 常駐・更新・プロセス管理

- 起動時と既定5分間隔で更新。パネルを開いた時は前回取得から1分以上経過していれば更新する。同時実行は一件にまとめる。
- スリープ中は更新を止め、復帰時は重複しないよう更新する。連続失敗時は5→10→20→30分へ間隔を延ばす。手動更新は待機を解除できる。
- Node/claude/codexの絶対パスを検出・保存し、設定で変更可能にする。GUI起動でも必要なPATHとアカウント探索先を渡す。シェル文字列を組み立てず、実行ファイルと引数を分ける。
- 全体タイムアウト、キャンセル、アプリ終了時にNodeとその子CLIを確実に終了させる。プロセスが残らないことを実機で確認する。
- `SMAppService` によるログイン時起動を設定から選べるようにする。

完了条件: Finder起動、再ログイン、スリープ復帰、ネットワーク断、一方のCLIのみ存在する場合で動作する。繰り返し更新後に残存プロセスが増えない。

### 4. ローカル導入と配布

- ローカルMVP: ビルド済みJSをapp bundleに含め、既存NodeとCLIを利用する。実行時にリポジトリの場所へ依存させない。
- 一般配布: 対象CPUを決め、Node同梱か別途インストール要件かを確定する。署名・公証したアプリを直接配布する方針を検証する。外部CLIとユーザーの設定ディレクトリを扱うため、App Sandboxの制約を初期に検証する。
- READMEにCLIとの関係、必要環境、更新方法、キャッシュ場所を記載する。

完了条件: 開発ディレクトリ外から起動できる。配布対象環境で初回起動と依存関係のエラー表示が確認できる。

### 最新のUI・取得仕様（ユーザー指定）

- 必須列はアカウント名、週間残り枠、リセットまでの相対時間。正確な日時はツールチップ。
- 短期枠・モデル別枠・リセット権は任意表示。初期状態では非表示、追加項目に応じて縦に拡張し、長い一覧のみスクロール。
- サービスフィルタとアカウント検索、週間リセット順（既定）・残量昇降順・アカウント名順。過去・不明のリセット日時は末尾。
- 取得はパネルを開いたときと手動更新のみ。定期タイマー・起動時・復帰時の自動取得は廃止。閉じる前に開始した照会は完了まで継続する。
